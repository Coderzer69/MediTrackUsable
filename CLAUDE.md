# MediTrack — project notes for Claude Code

Handoff from a Claude chat session (Nov 20–21, 2026). Read this first.

## Layout
- `Backend/` — Express 5 + TypeScript (run with `tsx`), Prisma 5.22, Neon Postgres. Port **3000**.
- `Frontend/` — main app (React 19 + Vite 8 + Tailwind v4). Port **5173**. Patients, doctors, and an admin dashboard at `/admin/dashboard`.
- `admin/` — separate admin portal (React + Vite + Tailwind v4, HashRouter). Port **5174**.
- `admin copy/` — stale duplicate of `admin/`; not used.

## Running (Windows)
- `restart-all.bat` — frees ports 3000/5173/5174, then starts all three (`run-backend.bat`, `run-frontend.bat`, `run-admin.bat`). Output goes to `logs/*.log`.
- The backend does NOT hot-reload — restart after backend changes.
- Vite configs use polling (`server.watch.usePolling`) because the repo lives in OneDrive.
- Demo logins (password `password123`): `admin@meditrack.com`, `doctor@meditrack.com`, `patient@meditrack.com`.

## Helper scripts (project root)
- `db-check.bat` → `Backend/db-check.ts`: read-only row counts → `logs/db-check.log`.
- `db-push.bat`: `prisma db push --skip-generate` (adds missing tables; refuses data loss).
- `test-signup.bat`, `test-doctor-profile.bat`, `test-medical-records.bat`: end-to-end API checks using throwaway `synctest.*@example.com` accounts that they delete afterwards. Results in `logs/`.

## Conventions / decisions made
- **Auth sessions are per-tab**: `Frontend/src/lib/session.ts` (sessionStorage, last login mirrored to localStorage for new tabs). Route guards send wrong-role users to their own dashboard (`dashboardPathForRole`).
- **ADMIN is superuser**: `Frontend/src/lib/access.ts` (`canAccessRole`, `canUseDoctorFeatures`); backend `requireRole` lets ADMIN through; `doctorController` uses `isAdminRequest` / `doctorScope` so admin sees all data and never gets fake profile rows created.
- **One email = one role**: Google sign-up with an account already registered under another role returns 409 `ROLE_CONFLICT` (authController `oauthLogin`). No silent patient→doctor upgrade.
- **Missing doctor profile** is recreated as `INCOMPLETE` (never auto-approved).
- **Dark/light theme**: `ThemeContext` + `ThemeToggle` in both apps; dark colors are generated by `scripts/dark-theme.mjs` (Vite plugin) into `src/theme-dark.generated.css` — do not edit that file by hand; use `dark:` classes to override.
- **Live sync**: `GET /api/admin/sync-state` returns a fingerprint of admin tables; `lib/liveSync.ts` polls every 5 s and silently reloads admin views (both admin UIs).
- **Medical records**: patient uploads stored PRIVATELY in `Backend/private-uploads/medical-records` (gitignored), served only via authenticated routes. Logic in `Backend/src/utils/medicalDocuments.ts`. Patient: `/api/patient/documents` (+ `/:id/file[?download=1]`, DELETE). Doctor read-only: `/api/doctor/patient/:patientId/documents[/:documentId/file]`, requires an APPROVED, unexpired history-access request. UI: `PatientMedicalRecords.tsx`, `PatientRecordsPanel.tsx`, `RecordList.tsx`, `RecordPreviewModal.tsx`.
- Doctor names: use `withDr()` from `Frontend/src/lib/names.ts` (avoids "Dr. Dr.").
- Doctor verification dropdown options live in `Frontend/src/lib/doctorOptions.ts`.

## Deployment (Render)
- `render.yaml` Blueprint: `meditrack-api` (web, Backend/), `meditrack-web` and `meditrack-admin` (static).
- Files are stored in the DB (`StoredFile` table, `src/utils/fileStore.ts`); local folders are only fallbacks.
- `oauthLogin` accepts only Google ID tokens verified against GOOGLE_CLIENT_ID; sign-up roles limited to PATIENT/DOCTOR.
- CORS is limited to `CORS_ORIGINS` in production.
- `deploy-1/2/3-*.bat`: schema diff (read-only) → apply reviewed SQL + import files → commit & push.

## Known issues / suggested next steps
- **Security:** `oauthLogin` accepts unverified fallback emails (`isGoogleAuth` / `fallbackEmail` / decoded-but-unverified tokens) — anyone can log in as any email. Must fix before deploying.
- Files in public `Backend/uploads/` (doctor licence docs, avatars) are served without auth via `/uploads`. Should move to the private pattern used for medical records.
- Avatar upload endpoints + `User.avatarUrl` exist but no UI uses them.
- `validateAndNormalizeConsultation` in `doctorController.ts` was restored from the last git commit after an accidental deletion; re-check if it had uncommitted edits.
